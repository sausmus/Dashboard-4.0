GOOGLE CLASSROOM ROSTER SYNC — SETUP & TESTING

This Dashboard build uses Google Classroom only. It does NOT use Google Drive
or Teacher Dashboard cloud sync.

1. GOOGLE CLOUD PROJECT
   Use a Google Cloud project you control.

2. ENABLE THE GOOGLE CLASSROOM API
   In Google Cloud Console, enable:
   - Google Classroom API

3. OAUTH WEB CLIENT
   Create (or use) an OAuth 2.0 Client ID of type "Web application".

   Add the Dashboard's HOST ORIGIN to Authorized JavaScript origins.

   For GitHub Pages, this is normally:
   https://YOUR-GITHUB-USERNAME.github.io

   Do not include the repository path in the JavaScript origin.

4. OAUTH CONSENT / DATA ACCESS
   This build requests only:
   - https://www.googleapis.com/auth/classroom.courses.readonly
   - https://www.googleapis.com/auth/classroom.rosters.readonly

   If your OAuth app is in External / Testing mode, make sure the Google account
   you will use to test Classroom is permitted as a test user when required by
   your Google Cloud configuration.

5. PUT THE CLIENT ID IN THE DASHBOARD
   Host this build (for example with GitHub Pages), open:

   Dashboard -> Settings -> Google Classroom

   Paste the OAuth Web Client ID ending in:
   .apps.googleusercontent.com

   Click:
   Save Client ID

6. CONNECT
   Click:
   Connect Google Classroom

   Approve the read-only Classroom permissions. The Settings page should then
   display the number of active courses found.

7. MAP COURSES
   For each Dashboard period, choose the matching Google Classroom course.

   Example:
   Period 1  ->  English 8 - Period 1
   Period 2  ->  English 8 - Period 2

   Mappings are saved immediately when selected.

8. IMPORT ROSTERS
   Click:
   Import All Mapped Rosters

   Or use Refresh Roster beside one mapped period.

9. VERIFY
   Confirm each mapped row reports the expected student count and a Last
   imported timestamp.

   Then check Master Rosters and open Student Picker / Participation Tracker.
   The existing utilities should see the imported student names normally.

DATA MODEL
The Dashboard still exposes its existing simple roster to older utilities:

  ["John Smith", "Jane Doe"]

But Classroom identity information is retained separately:

  {
    id: "112233445566",
    name: "John Smith",
    source: "googleClassroom",
    courseId: "123456789"
  }

This stable ID layer is what we will use later when Participation is upgraded
for Google Classroom grade syncing.

CURRENT LIMITATION
The older Dashboard utilities still identify students by name. If a class has
two students with exactly the same full name, the legacy roster layer cannot
reliably distinguish them yet. The Classroom identity layer keeps both Google
IDs; native ID support in Picker/Participation is a later milestone.

TROUBLESHOOTING
- "Save your Google OAuth Web Client ID first."
  -> Paste the Web Client ID in Settings and save it.

- origin_mismatch / OAuth origin error
  -> Add the exact site origin to Authorized JavaScript origins. For normal
     GitHub Pages repos, use https://YOUR-GITHUB-USERNAME.github.io

- API has not been used / accessNotConfigured
  -> Enable Google Classroom API in the same Google Cloud project as the OAuth
     client.

- permission / access denied
  -> Confirm you selected the teacher Google account and that the OAuth consent
     configuration permits that account.

- session expired
  -> Click Connect Google Classroom again. Access tokens are intentionally not
     stored as a Dashboard cloud-sync feature.
